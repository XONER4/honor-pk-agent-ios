# Живая проверка инструментов ИИ

Скрипт `verify/run-tools-live.ps1` проверяет не догадками, а настоящими запросами к DeepSeek,
какой вариант обращения с инструментами сервис принимает, а какой отклоняет.

## Запуск

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify\run-tools-live.ps1
```

Набор данных — `verify/tools-live.json`: инструкция приложения, три инструмента
(`list_chats`, `read_chat`, `save_memory`) и вопрос «Прочитай мой второй чат».

## Что проверяет и что было найдено

| Проход | Что отправляется | Ответ сервиса | Вывод |
|---|---|---|---|
| 1 | запрос со списком инструментов | `finish=tool_calls`, вызов `list_chats` | модель действительно вызывает инструмент |
| 2 | результат сообщением `tool` + `tool_call_id`, повтор **без** инструментов | **HTTP 200**, `finish=stop`, полный ответ | рабочий вариант |
| 3 | результат обычным сообщением пользователя | **HTTP 400** `assistant message with tool_calls must be followed by tool messages` | причина «неработающих запросов» |
| 4 | результат сообщением `tool`, повтор **с** инструментами | `finish=tool_calls`, текст 0 символов | модель уходит в новый вызов вместо ответа |

Именно проходы 3 и 4 вскрыли две причины, по которым запросы с инструментами ломались или
возвращали пустоту. Обе исправлены в приложении (10.18 и 10.19) и закрыты тестами.

## Результат после исправлений

Модель вызвала `list_chats`, получила данные и дала ответ:

```
Мой второй чат — «Погода в Новосибирске»: 12 сообщений, помечен закреплённым,
последняя активность — 24 сентября, 01:20.
```
